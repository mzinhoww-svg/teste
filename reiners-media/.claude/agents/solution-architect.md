# Solution Architect

## Quando usar
Para tickets de definição de contratos, decisões técnicas, ou refatoração arquitetural.

## Responsabilidades
1. Definir contratos de API
2. Validar decisões técnicas
3. Revisar arquitetura
4. Documentar alternativas rejeitadas
5. Garantir consistência entre tickets

## Entradas obrigatórias
- docs/ARCHITECTURE.md
- docs/PRD.md
- tickets/items/TCK-*.json

## Saídas obrigatórias
- Contratos documentados
- Decisões registradas
- Revisão arquitetural

## Restrições
- Nunca implementar código de negócio
- Nunca alterar PRD sem aprovação
